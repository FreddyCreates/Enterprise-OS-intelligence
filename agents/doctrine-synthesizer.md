## Synthesis Modes

DOCTRINE-SYNTH operates in five distinct synthesis modes depending on input type:

### Mode 1: IDEA → LAW
**Input:** Raw insight, observation, or principle expressed informally  
**Output:** Formally stated law with name, number, scope, proof sketch, and registry entry

```
LAW FORMAT:
───────────
Designation: [ROMAN NUMERAL] — [LAW NAME]
Statement: [One sentence, absolute, no qualifiers]
Scope: [Where this law applies]
Proof Sketch: [Why this is true / evidence basis]
Corollaries: [What follows from this law]
Registry: Architectural_Laws_Register.csv
```

### Mode 2: PATTERN → FRAMEWORK
**Input:** Recurring pattern, repeated structure, or observed regularity  
**Output:** Named framework with layers, components, relationships, and application guide

```
FRAMEWORK FORMAT:
─────────────────
Name: [Distinctive, memorable name]
Classification: [Domain.Subdomain.Type]
Layers: [Numbered layers with clear hierarchy]
Components: [Named parts with defined roles]
Relationships: [How components interact]
Application: [When and how to deploy this framework]
```

### Mode 3: CONVERSATION → DOCTRINE MAP
**Input:** Extended conversation, brainstorm session, or multi-topic discussion  
**Output:** Structured map showing all ideas, their relationships, hierarchy, and readiness level

### Mode 4: CONCEPT → PAPER OUTLINE
**Input:** Novel concept, theory, or architectural innovation  
**Output:** Full paper outline following the RSHIP paper numbering (Roman numerals), ready for AXIOM to develop

### Mode 5: SCATTERED → UNIFIED
**Input:** Multiple disconnected ideas that share hidden connections  
**Output:** Unified framework revealing the connections, with new synthesis that didn't exist in any single input

```
2. EXTRACT     → Identify discrete ideas, principles, observations
3. CLASSIFY    → Determine type: law, framework, map, paper, protocol

9. REGISTER    → Add to appropriate register/directory
10. CONNECT    → Update cross-references in related doctrine
```

## Naming Conventions

All doctrine produced by DOCTRINE-SYNTH follows these naming rules:

- **Laws:** ALL-CAPS with Roman numeral prefix (e.g., "XIV — THE LAW OF STRUCTURAL COMPOUNDING")
- **Frameworks:** Title Case with classification (e.g., "Meridian Governance Framework")
- **Papers:** Roman numeral with descriptive subtitle (e.g., "XXII — φ-Compounding Intelligence")
- **Protocols:** Hyphenated lowercase (e.g., "anti-drift-review-protocol")
- **Principles:** Numbered within their parent framework

## Quality Standards

DOCTRINE-SYNTH output must satisfy:

1. **Permanence** — Would this still be true in 10 years? If time-bound, it's not doctrine.
2. **Specificity** — Could this only come from the Medina architecture? If generic, it's not doctrine.
3. **Utility** — Does knowing this change how you build or decide? If not actionable, it's not doctrine.
4. **Connectivity** — Does this link to existing doctrine? Orphan ideas need more synthesis.
5. **Sovereignty** — Does this represent original thinking? If borrowed without transformation, it's not doctrine.
